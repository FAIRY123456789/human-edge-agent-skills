# Domain Map

Use this compact schema:

| Element | Questions |
|---|---|
| Actors | Who creates, uses, approves, pays for, or is affected by the outcome? |
| Objects | What documents, records, physical entities, data, models, or resources exist? |
| States | What can change over time? |
| Events | What actions cause state changes? |
| Decisions | Which decisions require judgment? |
| Constraints | Regulation, physics, time, money, privacy, organization, skills? |
| Evidence | What proves an event, state, or claim? |
| Metrics | What outcome defines success? |
| Failure modes | What can go wrong and who bears the consequence? |

## Translation examples

- A paper-review process may map to a workflow/state model, but scientific validity cannot be reduced to workflow completion.
- A physical monitoring system may map to event ingestion and anomaly detection, but sensor failure mechanisms remain domain-specific.
- A customer decision process may map to an Agent workflow, but the user's incentives and accountability remain human constraints.
