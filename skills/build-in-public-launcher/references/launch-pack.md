# Launch Pack

A credible public release should include:

1. Repository name with searchable problem keywords.
2. One-line tagline.
3. Three-sentence problem statement.
4. 30-second installation path.
5. One runnable example.
6. One visible before/after or task-success example.
7. Compatibility statement.
8. Privacy/security note when relevant.
9. License.
10. Contribution path.
11. Issue template or feedback path.
12. Changelog/release notes.
13. Primary proof metric.
14. Explicit disclosure of validation gaps.

## Metric distinction

- Stars/views = distribution.
- Installs = initial adoption.
- Successful task completion = utility.
- Repeat use = retained utility.
- External issues/PRs/integrations = ecosystem participation.
- Measured time/quality/business result = impact.
