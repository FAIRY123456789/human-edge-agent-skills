# Personal Design Logic

This collection is intentionally more personal than a generic productivity pack. It comes from a recurring way of working with AI and reality.

## 1. Read context before generating language

Social messages, voice transcripts, project names, and technical requests all contain context that a literal model can miss. The repository therefore repeatedly uses relationship distance, active glossary, conversation history, semantic fit, and explicit uncertainty before normalizing the output.

## 2. Keep the human in the loop where judgment matters

The model can draft quickly. The human still decides what is socially appropriate, which ASR correction is actually intended, what a project result proves, which trend deserves a bet, and whether an analogy across domains is valid.

## 3. Convert fuzzy thought into executable structure

Two Voice Native skills embody this directly:

- messy voice → executable to-do;
- messy voice → implementation-ready software spec.

The goal is not transcription quality by itself. The goal is reliable action after imperfect transcription.

## 4. Small bets beat abstract FOMO

New models, platforms and Agent ecosystems move too quickly for exhaustive learning. A trend becomes valuable only after it is converted into a cheap experiment, a proof metric, and a stop rule.

## 5. Scars should become reusable knowledge

Repeated deployment mistakes, prompt failures, writing corrections, user-research errors, or communication friction should gradually become reusable workflows. `skill-from-scars` makes that process explicit.

## 6. External proof matters more than private completion

A finished repository, local demo, article, or prototype is only one proof level. Public launch, successful task completion, repeat use, useful issues, downstream integration, and measurable results create stronger evidence.

## 7. Personal voice is an asset

Long-form writing should remain inhabited by a person. Clarity is useful; generic polish that removes lived detail, uncertainty, rhythm, or specific judgment is a regression.

## 8. Cross-disciplinary strength comes from structural translation

Actors, objects, states, events, constraints, evidence, metrics, and failure modes travel across fields more reliably than buzzwords.

## 9. A week needs a bet, not merely a list

When startup, research, career and creator work collide, the operating question becomes: what one result changes the next decision this week? `one-week-founder-mode` formalizes that choice.

## 10. Real machines and real bodies deserve conservative assumptions

Engineering on an existing server starts with inspection, isolation, backup and rollback. Fitness planning starts with sleep, fatigue, pain, recovery and safety. Existing reality gets priority over an elegant plan.
